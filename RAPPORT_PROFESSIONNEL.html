Ce projet implémente un système d'extraction intelligente de villes (départ/arrivée) à partir de commandes en langage naturel pour des réservations de train en français. Nous avons comparé trois approches : une baseline avec spaCy, le modèle de langage Qwen2.5 seul, et enfin Qwen2.5 combiné avec ChromaDB RAG pour une amélioration contextuelle.

🎯 Contexte et Problématique

Le Défi

Les utilisateurs réservent des billets de train en utilisant des formulations variées :

  • "Je veux aller de Paris à Lyon demain"
  • "Un billet pour Marseille depuis Toulouse svp"
  • "Train Bordeaux Nice dans l'après-midi"
  • "Direction Lille au départ de Strasbourg"

Objectif du Projet

Extraire automatiquement et avec précision la ville de départ et la ville d'arrivée à partir de ces commandes en langage naturel, quelle que soit la formulation utilisée.

Pourquoi c'est difficile ?

  • Variété de formulations : Des centaines de façons différentes d'exprimer la même chose
  • Ordre inversé : "De Paris à Lyon" vs "Lyon depuis Paris"
  • Contexte manquant : Parfois une seule ville est mentionnée
  • Ambiguïtés : Distinguer les noms de villes d'autres entités

🛠️ Technologies et Outils

🤖 Qwen2.5-3B-Instruct

Qu'est-ce que c'est ?

Un modèle de langage (LLM) de 3 milliards de paramètres développé par Alibaba. C'est une IA capable de comprendre et générer du texte en plusieurs langues dont le français.

Pourquoi l'utiliser ?

  • Excellente compréhension du contexte
  • Capacité de few-shot learning (apprend à partir d'exemples)
  • Multilingue natif (français supporté)
  • Taille optimale pour GPU (3B paramètres)

🗄️ ChromaDB RAG

Qu'est-ce que c'est ?

Une base de données vectorielle qui stocke des phrases avec leurs "embeddings" (représentations mathématiques). Le RAG (Retrieval-Augmented Generation) recherche les exemples les plus similaires pour améliorer les prédictions.

Pourquoi l'utiliser ?

  • Fournit des exemples contextuellement pertinents
  • Améliore la précision de +18 points !
  • Recherche vectorielle ultra-rapide
  • Adaptabilité dynamique aux requêtes

📚 spaCy (Baseline)

Qu'est-ce que c'est ?

Une bibliothèque NLP traditionnelle avec reconnaissance d'entités nommées (NER). Utilisée comme baseline pour comparer les performances.

Limites identifiées :

  • Confond souvent départ et arrivée (19%)
  • Détecte une seule ville dans 55% des cas
  • Manque de compréhension contextuelle

🎮 GPU NVIDIA RTX 3060

Infrastructure

  • 6GB de VRAM
  • PyTorch 2.5.1 + CUDA 12.1
  • Accélération 10-50x vs CPU
  • Temps: 6.6s/phrase sur GPU vs plusieurs minutes sur CPU

🔍 Comment fonctionne ChromaDB RAG ?

Le Processus en 4 Étapes

  1. Stockage : On charge 100 phrases annotées dans ChromaDB (ex: "Je veux aller de Paris à Lyon" → départ=Paris, arrivée=Lyon)
  2. Requête utilisateur : L'utilisateur demande "Train pour Marseille depuis Nice"
  3. Recherche vectorielle : ChromaDB trouve les 3 phrases les plus similaires dans sa base (basé sur le sens, pas juste les mots)
  4. Few-shot learning : Qwen2.5 utilise ces 3 exemples similaires pour mieux comprendre et extraire départ=Nice, arrivée=Marseille

Résultat : Au lieu d'utiliser toujours les mêmes exemples génériques, Qwen2.5 reçoit des exemples adaptés à chaque requête, ce qui améliore drastiquement la précision (+18 points : de 75% à 93% !).

🔬 Analyse Détaillée

Impact du RAG ChromaDB

Le RAG ChromaDB apporte un gain de +18 points d'accuracy (de 75% à 93%), soit une amélioration relative de 24% !

Cela démontre l'efficacité du few-shot learning adaptatif : en fournissant des exemples contextuellement pertinents, Qwen2.5 comprend mieux la tâche et génère des prédictions plus précises.

Pourquoi Qwen2.5 surpasse spaCy ?

  • Compréhension contextuelle : Qwen2.5 comprend le sens global de la phrase, pas seulement les mots
  • Gestion de l'ordre : Pas de confusion entre "Paris à Lyon" et "Lyon depuis Paris"
  • Robustesse : Fonctionne même avec des formulations inhabituelles
  • Few-shot learning : S'adapte en voyant seulement quelques exemples

Limitations

  • Vitesse : 6.6s/phrase sur GPU vs 0.5s pour spaCy (13x plus lent)
  • Ressources : Nécessite un GPU pour être performant
  • Complexité : Architecture plus complexe que spaCy

💡 Compromis Performance vs Vitesse

Pour un système de production, le choix dépend des besoins :

  • Précision critique : Utiliser Qwen2.5 + RAG (93% accuracy)
  • Volume élevé : Optimiser avec batch processing et GPU
  • Contraintes temps réel : Envisager un modèle plus petit ou quantization

🔧 Méthodologie

1. Dataset Génération

Nous avons généré automatiquement 10,000 phrases avec :

  • 131 villes françaises
  • 83 templates de formulation variés
  • 15% de questions, 10% avec dates, 4% avec contexte
  • 100% de phrases uniques

2. Tests Effectués

  • spaCy : 1,000 phrases testées
  • Qwen2.5 seul : 100 phrases testées
  • Qwen2.5 + RAG : 100 phrases testées avec 100 exemples ChromaDB

3. Infrastructure GPU

  • NVIDIA GeForce RTX 3060 Laptop (6GB VRAM)
  • PyTorch 2.5.1 + CUDA 12.1
  • Python 3.12 dans environnement virtuel
  • Vitesse d'inférence : 6.6s/phrase

✅ Conclusions et Recommandations

Conclusions Principales

  1. Qwen2.5 + ChromaDB RAG atteint 93% d'accuracy, dépassant largement l'objectif de 90%
  2. Le RAG apporte un gain significatif de +18 points, démontrant l'efficacité du few-shot learning adaptatif
  3. L'infrastructure GPU est opérationnelle et performante (RTX 3060)
  4. Le dataset de 10,000 phrases est prêt pour un éventuel fine-tuning futur

Recommandations pour la Production

Court Terme

  • Déployer Qwen2.5 + ChromaDB RAG comme solution principale
  • Implémenter batch processing pour traiter plusieurs requêtes simultanément
  • Créer une API REST pour faciliter l'intégration
  • Monitorer les performances en production

Moyen Terme

  • Augmenter le dataset RAG à 1,000-5,000 phrases pour plus de couverture
  • Fine-tuning de Qwen2.5 avec LoRA/QLoRA sur le dataset 10k
  • Optimisation GPU avec quantization INT8 pour réduire la VRAM
  • Implémenter Flash Attention pour accélérer l'inférence

Long Terme

  • Explorer des modèles plus grands (Qwen2.5-7B) si le matériel le permet
  • Étendre à d'autres langues (anglais, espagnol, etc.)
  • Intégrer des fonctionnalités supplémentaires (dates, horaires, préférences)
